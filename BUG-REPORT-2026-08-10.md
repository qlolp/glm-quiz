## 🐛 Найденные баги

### BUG-A. Rate limit (30/мин) ломает прохождение викторины [P0]

**Воспроизведение:** Пройти 84 вопроса в тренировочном режиме без пауз.
На ~30-м вопросе `checkAnswer()` получает HTTP 429.

**Симптом:** Экран "Не удалось проверить ответ. Проверьте соединение."
Кнопки "Попробовать снова" и "Сбросить кэш".

**Root cause:** Rate limit на `/api/quiz/check-answer` — 30 запросов/минуту (FEEDBACK_RATE_LIMIT).
Для викторины из 84 вопросов при скорости ~1 ответ/сек пользователь упирается в лимит на 30-м вопросе.

**Workaround в коде:** В `user.js` добавлен retry с backoff (2→4→8 сек), но browser_console
зависает при ожидании retry внутри async функции (30s timeout CDP).

**Рекомендация:** Поднять `FEEDBACK_RATE_LIMIT` до 120/мин для check-answer, либо исключить
`/api/quiz/check-answer` из feedback rate limiter — это не feedback, это core quiz flow.

**Файлы:** `server/server.js:237` (FEEDBACK_RATE_LIMIT=30)

### BUG-B. "Профиль" в шапке ведёт на /my-certificates.html [P2]

**Воспроизведение:** Залогиниться → наведите на "Профиль" в правом верхнем углу.

**Симптом:** Ссылка "Профиль" (`regLink`) указывает на `/my-certificates.html`,
а не на страницу профиля пользователя. Страница "Мои сертификаты" показывает
достижения и сертификаты, но не профиль (имя, организация, статистика).

**Root cause:** `index.html:3131-3132`:
```javascript
regLink.textContent = 'Профиль';
regLink.href = '/my-certificates.html';
```

**Рекомендация:** Либо переименовать ссылку в "Мои сертификаты", либо создать
отдельную страницу профиля.

---

### BUG-C. Пустой `<img>` тег создаёт битый запрос [P3]

**Воспроизведение:** Открыть главную страницу, проверить DOM.

**Симптом:** `<div class="question-media"><img src="" alt="Изображение к вопросу"></div>`
— пустой src рендерится как битый image request на текущий URL страницы.

**Рекомендация:** Скрывать `div.question-media` или не рендерить `<img>` при отсутствии src.

**Файл:** `public/index.html` (контейнер вопроса)

### BUG-E. Service Worker кэширует старую версию user.js [P2]

**Воспроизведение:** Внести изменения в `user.js` → обновить страницу → старый код
выполняется из SW-кэша.

**Симптом:** Retry logic на 429 (добавленная в user.js) не срабатывает в браузере,
потому что SW отдаёт старую версию файла.

**Root cause:** `sw.js` STATIC_CACHE_URLS включает `'/js/user.js'` без content-hash.
Версия кэша: `2026.08.01.1`. Без изменения версии SW кэш не инвалидируется.

**Рекомендация:** При деплое обновить `STATIC_CACHE_VERSION` в `sw.js`.
