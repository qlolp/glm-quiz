### 🟦 LOW FIND-R2-1 — answer вне диапазона 0-3 принимается в /api/competency/update
Где: server.js:3221 — `if (answer.answer === question.correct_answer)`

Что:
  Сервер сверяет `answer === correct_answer`, но не валидирует
  `answer ∈ [0, 3]` для 4-вариантных вопросов. Out-of-range значения
  (например 99) обрабатываются как "incorrect" (не совпадают с 0-3)
  и инкрементят total_count.

Тест: POST /api/competency/update {"answers":[{"questionId":8,"answer":99}]}
  → success, updated_categories:[documentation], correct=0, total=1

Риск: низкий — `proficiency %` НЕ растёт потому что correct не инкрементится.
Злоупотребление — засор `competency_matrix` при множественных submit.
Может использоваться как amplification для нагрузки БД в тысячи раз.

Что делать:
  В server.js:~3207 добавить валидацию диапазона:
    if (answer.answer < 0 || answer.answer > 3) continue;
  Или: если max-option-per-question можно прочитать из question.options:
    if (answer.answer < 0 || answer.answer >= optionCount) continue;

Приоритет: LOW — не блокер для seminar 25-27. Хорошее small-fix.
