    Тест: code=12345 → "Invalid or expired verification code"
    Тест: code=1234567 → "Invalid or expired verification code"

[✅ FIX P1] Утечка данных отдела /api/competency/department/:dept_name

[✅ FIX P1] Anti-cheat /api/quiz/complete — legacy question_index+is_correct

### 🟥 CRITICAL FIND-1 — DEMO_MASTER_CODE=1234 в проде работает
Где: server.js:2029 (/api/auth/admin нет, но /api/auth/verify принимает
master) + VPS .env содержит DEMO_MASTER_CODE=1234

Что: ЛЮБОЙ email, не существующий в БД, после register может пройти
verify через code=1234 → получить валидный user-token (181 байт JWT).

Риск: 
  - Если .env с DEMO_MASTER_CODE попадёт в public deploy — это реальная
    дыра. Прямо сейчас значение в .env и в changelog-е одинаковое.
  - На 25-27 августа, когда участники получат доступ, любой
    недобросовестный участник может массово создавать аккаунты
    без email-confirmation.

Тест: зарегистрировал audit_v4_2367286@example.com → verify с code=1234
→ success, token готов за ~250ms.

Что делать:
  - [СРОЧНО] Если прод ≠ только тест — убрать DEMO_MASTER_CODE из VPS
    .env или сменить на длинный случайный (16+ символов).
  - [СРОЧНО] Использовать DEMO_MASTER_CODE только при NODE_ENV !== 'production'
    — server-side guard. Если этого нет, добавить.
  - Если решено оставить для seminar демо-режима — документировать и
    вынести переменную в отдельный config (НЕ в .env рядом с прод-
    секретами), чтобы rotate не путать с продом.

### 🟧 MEDIUM FIND-2 — Quiz complete replay (no server-side dedup)
Где: server.js POST /api/quiz/complete

Что: Найденный anti-cheat считает "score does not match answers", но
НЕ проверяет, что этот конкретный quiz уже был завершён. Повторный
запрос с тем же payload'ом инкрементирует total_score.

Тест:
  POST /api/quiz/complete {"score":1,"total_questions":1,"answers":[{"questionId":1,"answer":0}]}
  → success:total_score=1
  (повторно) → success:total_score=2
  (повторно ×3 подряд) → total_score=3,4...

Каждый repeat — это +1 к total_score, +achievements могут дублироваться,
лидерборд score растёт.

Что делать:
  - Серверный дедуп: (user_id, question_hash) UNIQUE или session_id из
    адаптивного сеанса — INSERT в completed_results с UNIQUE на
    (session_id,user_id). Если уже есть — 409 Conflict.
  - Альтернатива: rate-limit на /api/quiz/complete срабатывает
    (после 4-5 повторов → 429), но это мягкий guard, атакующий умеет
    экспоненциальный backoff.

### 🟧 MEDIUM FIND-3 — /api/competency/update с client-trusted is_correct
Где: server.js стр. 3166

Что: Score growth через mass-insert с is_correct=true в payload.
   POST /api/competency/update
   {"answers":[{"category":"ethics","is_correct":true},...]}
   → success, updated_categories:[ethics,rights]
   Каждое обращение инкрементит correct_count на клиентский флаг.

Тест: я добавил 3 ответа "correct" себе, server принял, total_score
вырос. Server и так берёт user_id из req.userId (правильно), но
is_correct-флаг от клиента.

Что делать:
  - Либо обнулить /api/competency/update и считать competency из
    quiz_results server-side (только admin может инжектить для
    импорта извне).
  - Либо сделать requires-server-verified: для каждого questionId
    в payload проверить в quiz_results, что user реально ответил
    правильно.
